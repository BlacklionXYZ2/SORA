## Implementation

- Core now has a versioned, strict, credential-free owner-local runtime settings
  file. The settings API validates exact fields and a safe OpenAI-compatible
  `/v1` endpoint, rejects stale revisions, and stages changes for the next
  clean Core start. Saved settings override matching startup defaults while
  leaving API keys, grants, content roots, handler executables and managed
  workspaces in their protected setup paths. A first save creates a durable
  revision even when its values match the current startup defaults.
- The full app edits direct dialogue provider/model/endpoint/timeout, worker
  count and context maximum. It shows pending versus active revisions, keeps
  unsaved drafts intact across polling, and never puts these values or secrets
  into its local tab/technical-detail preference file. Protected setup and
  permission scopes remain redacted read-only projections.
- `POST /api/v1/settings` is owner-local only. The paired remote allowlist does
  not expose either the settings write or the settings projection.
