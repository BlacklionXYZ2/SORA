## Changes implemented

- Added the public `DesktopTypeRequest` contract and extended the durable desktop-action result to
  distinguish PRESS and TYPE. Regenerated the versioned schemas.
- Added exact `desktop.interact:<target-id>:type` authorization, fresh contact-time target
  revalidation, grant consumption, durable attempt reservation/compare-and-set transitions,
  duplicate suppression and restart/cancellation unknown-outcome behavior.
- Added Core-held prepared TYPE sessions. Target authority and text remain in volatile Core memory;
  Unity receives only geometry, semantic action and opaque attempt ID.
- Added the separately configured `clients/windows_type` .NET 10 worker. It is one-shot,
  credential-free, shell-free and non-elevating; rechecks process/control identity, geometry,
  enabled/offscreen/password/read-only state; uses UIA `ValuePattern.SetValue`; and independently
  verifies the exact resulting value.
- Prevented password controls from becoming reusable desktop targets. TYPE has no synthesized
  keyboard/input fallback and therefore does not claim terminal or credential-field support.
- Extended the owned UIA fixture with a normal text field and deterministic value evidence.
- Added `AuthorizedTypeAction` as an independent registry component. It uses the unchanged generic
  Navigate/Align/Reach/Contact/Effect/Verify/Retract controller and existing presentation-profile
  lookup; POINT and PRESS implementations were not modified to enumerate TYPE.
- Added route/client support for direct and embodied TYPE plus the contact-only prepared-interaction
  endpoint shared with PRESS.
- Added deterministic moved-target, exact-grant, duplicate, cancellation, privacy, password-target,
  worker protocol and Unity outcome fixtures, plus real UIA and packaged-player acceptance.

## Boundaries

- The initial TYPE operation is an exact semantic replacement through UIA ValuePattern, not physical
  keystroke synthesis, terminal input or detailed keyboard animation.
- Typed text is sent only from Core to the bounded worker. It is hashed into the action request
  identity but absent from the durable action payload, Unity command and Unity evidence.
- Cancellation after the native effect claim is `unknown_outcome` and is never automatically
  repeated. The deterministic worker's exact-value verification distinguishes completion.
- Detailed keyboard presentation remains P15.12 polish.
