## Why this repair was needed

The original API passed its recorded suite, but review found gaps in replay pagination, RFC 6455 client/server framing, protocol bounds, shutdown cleanup, owner/device/project scoping, error disclosure, URL credential detection, IPv6 host validation, and extension authorization. A caller could also self-assert an integration approver through a legacy request body.

## Changes implemented

### HTTP and local boundary

- Added bounded header/body parsing, structured protocol errors, malformed length/header rejection, request and WebSocket hello timeouts, and HTTP 408 support.
- Rejected wildcard origins and credential-like query keys case-insensitively, including token, bearer, secret, credential, API-key, and key variants.
- Canonically parses bracketed IPv6 loopback hosts and requires exact origin scheme/host matching rather than prefix matching.
- Added the device/grant headers to CORS preflight handling.
- Writes generated token files atomically with owner-only permissions where supported.
- Sanitized unexpected route/provider failures while retaining server-side exception logs.

### WebSocket protocol and lifecycle

- Implemented client masking, required masking direction by endpoint role, fragmentation assembly, control-frame constraints, RSV/opcode validation, UTF-8 validation, payload/message bounds, close handling, and handshake key/version validation for the supported RFC 6455 text protocol.
- Verifies the server's `Sec-WebSocket-Accept` value in the client.
- Tracks active WebSockets and closes them during server shutdown; HTTP and WebSocket tasks are bounded and cleaned up independently.
- Readiness now probes provider capabilities as well as the database and reports degraded providers without exposing raw exception text.

### Durable replay and reconnect

- Captures a replay high-water sequence and pages through every durable event up to it instead of silently stopping after one page.
- Registers the live subscription before replay to eliminate the replay/live registration gap; clients deduplicate overlap by envelope sequence.
- Detects expired/negative cursors, sends `resync_required` plus an authoritative snapshot, and resets client ordering state before continuing.
- Treats a non-contiguous client sequence as a reconnect condition rather than accepting a silent gap.
- Closes slow clients without blocking Core and closes active streams during graceful restart.

### Scope, authorization, projections, and extensions

- Owner-scoped task, workspace, companion, and object queries; orphan workspace records now fail closed.
- Validated positive bounded pagination and message limits.
- Dangerous workspace validation/integration/rollback operations require an exact persisted grant tied to owner, device, project, operation, resource, and approved actor.
- Removed request-body `authorized_by` support from the SDK and API path.
- Object projections now expose stable referent and artifact IDs.
- Extensions start disabled, persist enabled state atomically, expose versioned schemas lazily, and require the configured exact persisted grant to enable.
- Active extension capabilities are resolved against the requesting device/project on every projection, so disable, revoke, expiry, exhaustion, or cross-device access invalidates them immediately.

## Tests added or strengthened

- Credential-query variants, wildcard origins, exact-origin rejection, and bracketed IPv6 loopback handling.
- Client masking and rejection of unmasked client frames.
- Replay of 35 offline events with a replay page size of 10, with exact sequential delivery.
- Independent client shutdown/restart behavior and active socket cleanup.
- Owner isolation, negative pagination, missing/wrong grants, and a request-body self-assertion attack.
- Default-disabled extensions, missing-grant rejection, lazy schema loading, persisted state, cross-device invalidation, disable, and revoke behavior.
- Projection referent/artifact identifiers and revision data.
