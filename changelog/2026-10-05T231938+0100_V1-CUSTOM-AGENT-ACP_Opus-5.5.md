# Custom agents can use the Agent Client Protocol as well as an OpenAI-compatible API

Model name: **Opus 5.5**. Checkpoint **2026-10-05 23:19:38 +01:00**, Europe/London. Status:
**implemented, component-tested only**. Moves [V1.md](../V1.md) step 7 forward. Done at the
owner's request: "The custom adapter should allow the user to choose … add an option and
functionality for ACP".

## Changes

- **Settings** (`CustomEndpoint` in `src/sora/runtime/agent_preferences.py`, still v10, which has
  not shipped beyond this branch): each custom-agent slot gains `protocol`
  (`openai-compatible` or `acp`), `command` and `arguments`.
  - An enabled OpenAI-compatible slot needs a port, and an enabled ACP slot needs a command.
  - Settings now has 129 fields, shown with ACP-specific labels and help text.
- **Adapter:** `CustomACPProvider` in `src/sora/providers/custom_endpoint.py` reuses the existing
  Hermes ACP client.
  - It launches the owner's command once per task and talks ACP over stdio (initialize,
    session/new or session/load, session/set_model, session/prompt), answering each permission
    request once.
  - It credits results to the nickname, accepts prose answers through the shared normaliser, and
    can work directly in a selected project folder (`ProjectRootProvider`).
  - `split_command_arguments` splits owner-typed arguments on whitespace. Double quotes group a
    value, and Windows backslashes are kept.
- **Hermes adapter** (`src/sora/providers/hermes.py`): the prompt text, result normalisation and
  error labels are now overridable methods and attributes. Hermes' own behaviour is unchanged.
- **Startup** (`src/sora/__main__.py`): enabled slots are registered according to their protocol.
  An ACP slot whose command is not found is skipped and listed among the skipped specialists.
- **Docs and config:** the local try-out runbook and the `V1.md` Agents row were updated, and
  `config/sora-settings.example.json` and the exported schemas were refreshed.

## Verification (component and fixture only)

- `pytest`: 949 passed / 29 skipped / 4 strict expected failures. The 8 failures are the same
  Linux-only ones as before. New tests in `tests/providers/test_custom_endpoint.py`: a fake ACP
  agent answers in prose and accepts a model switch, a run works in a project folder, a missing
  command is reported unavailable, and there are tests for validation, argument splitting and
  startup registration and skipping. The Hermes tests are unchanged and pass.
- `ruff` and `mypy --strict --platform win32`: clean. Schema export check: clean.
- `dotnet test`: 353 passed / 16 failed, the same Windows-only failures as before. No C# change
  was needed, because the Settings editor renders the new enum and string fields generically.

## Limits

- Not run against a real ACP agent or on the owner's machine.
- The arguments field is not a shell: there is no variable expansion or escaping beyond double
  quotes.
- Model discovery (Refresh in the Agents panel) for an ACP slot uses the Hermes catalogue probe,
  which expects the agent to list models on session/new.
