# Spoken requests that need a window now reach the action

Model name: **Opus 5.5**. Checkpoint **2026-10-09 20:30:00 +01:00**, Europe/London. Status:
**fixed and covered by tests; not yet re-tested live by voice.** The owner's test: always-on
listening and speech worked, but spoken "walk to the Claude window" and "walk around" did
nothing, and asked about her tools she named only task delegation. Typed, she walked.

## Diagnosis (from the owner's traces, read from a copy of the database)

- Spoken turns **were** offered every tool (`move`, `pose`, `look`, `point`, files, windows,
  delegation). Voice did not lose access.
- On spoken turns E4B chose `list_windows` although Core had already listed the windows for the
  turn. The repeat guard answered the first repeat with a pointer and ended the reading on the
  second, so she never reached `move`. Four spoken turns did this; the typed ones went straight
  to `move`. The prompt itself told her "list_windows first".
- "Claude" was transcribed as "cloud" once, so there was no matching window to name.
- "What tools do you have?" chose `list_agents` three times. The reply then saw only the agent
  list, so she described delegation as everything she could do.

## Changes

- `runtime/read_turn.py`:
  - once the windows are listed (seeded or called), `list_windows` is no longer offered that turn;
  - after the seeded list, any window the owner's words name is pointed out up front
    (`window_hint`);
  - `offered` in the trace still records the turn's full set;
  - new `abilities()` turns the offered operations into plain words.
- `runtime/service.py`: the reply context gains `[WHAT I CAN DO THIS TURN]` from `abilities()`.
- `contracts/companion_call.py`: the move guidance says to use the turn's window list and to
  list windows only when none is present.
- Tests: two new cases in `tests/runtime/test_companion_reads.py`.
