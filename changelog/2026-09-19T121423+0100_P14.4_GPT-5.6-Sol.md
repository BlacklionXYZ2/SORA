# P14.4 mouth and emotion synchronization — GPT-5.6 Sol

Completed: **2026-09-19 12:14:23 +01:00**.

## Changes

- Replaced opaque TTS bytes with validated, ordered, client-local signed-16 PCM chunks carrying sample
  rate and channel metadata.
- Added a monotonic audio presentation clock and validated amplitude fallback using normalized RMS,
  a noise floor, bounded gain and attack/release smoothing.
- Bound every presentation frame to playback ID, output epoch, exact chunk sequence and cumulative
  audio position so stale callbacks cannot animate another turn.
- Added a coarse utterance-level emotion to playback commands. Per-frame mouth or viseme fields remain
  absent from Core contracts and published schemas.
- Integrated presentation begin/frame/reset calls with speaker playback and every completion, pause,
  interruption, device-loss, disconnect and failure path.
- Added a Unity VRM voice presentation controller that maps mouth openness to `ExpressionKey.Aa` and
  bounded emotion to standard happy/relaxed/sad/neutral expressions.
- Kept Unity voice frames out of `EmbodimentCommandDto` and the Core command registry, preventing
  language-model frame commands.
- Added deterministic PCM, clock, smoothing, reset, stale-turn and public-contract tests plus six
  Unity PlayMode cases.
- Updated the root and Unity READMEs, implementation plan, generated schemas and acceptance evidence.

## Boundary

The tested implementation validates audio-derived clocks, amplitudes, reset semantics and Unity VRM
expression state. It does not claim observed physical microphone/speaker audiovisual alignment or
subjective animation quality. The initial fallback uses one `aa` mouth shape; phoneme/viseme adapters
can replace it without changing Core or giving models frame control.
