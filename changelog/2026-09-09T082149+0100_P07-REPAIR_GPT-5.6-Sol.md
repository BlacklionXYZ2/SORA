## Why this repair was needed

The original implementation passed its recorded suite, but adversarial review found correctness and safety gaps: forced workspace discard could lose untracked bytes, cleanup could delete a still-leased workspace, fan-out could launch one provider twice while leaving branch records pending, synthesis compared combined candidate diffs as though they were per-file evidence, and integration trusted caller-supplied identity text rather than persisted authorization evidence.

## Changes implemented

### Workspace recovery and lifecycle

- Added a verified `untracked-files.zip` recovery artifact before forced discard or orphan recovery. Binary files are preserved byte-for-byte, symlinks are recorded without following them, archive members are containment-checked, and CRC verification runs before the source worktree is removed.
- Made cleanup fail closed for unreadable leases and skip active, unexpired leases even when the age threshold is zero.
- Added isolated per-file diff extraction for truthful synthesis evidence.
- Preserved raw Git diff transport and made Windows CRLF integration work without accepting a dirty target checkout.

### Fan-out and provider isolation

- Removed the duplicate coordinator/provider submission path. A coordinator task is persisted directly, while each provider receives exactly one branch run.
- Added explicit branch-run lifecycle transitions so branch records finish as completed, failed, timed out, or cancelled rather than remaining pending.
- Enforced `max_branches >= 1`, unique provider names, and timeout coverage around provider startup as well as result collection.
- Added the `OwnedWorkspaceProvider` contract. Codex-managed behavior remains intact, while Hermes and Antigravity clone their adapters into the manager-owned branch worktree and continue to manage their own native tools.
- Kept provider failures visible in synthesis and failed the coordinator truthfully when every branch fails.

### Synthesis correctness

- Added per-file candidate diffs and compare those exact artifacts for agreement.
- Prevented a combined multi-file diff from being reused as the evidence for every changed file.
- Retained missing evidence and partial/all-failure states instead of manufacturing consensus.

### Authorization, integration, and rollback

- Added persisted operation authorization joining an exact capability request, active grant, approved approval record, policy decision, owner, device, project, operation, and resource.
- Removed `authorized_by` from public client, runtime, and review method inputs. The approving actor is now derived only from the persisted approval record.
- Atomically consumes bounded grants before privileged validation, integration, or rollback side effects.
- Rejects empty integrations and pre-existing staged target changes.
- Applies and commits only the selected tracked diff, preserves unrelated dirty/untracked files, restores only affected paths after failure, and reverts an integration if its durable record cannot be written.
- Records grant/approval attribution on integration and grant/actor attribution on rollback.

## Tests added or strengthened

- Exact binary untracked-file recovery and archive verification.
- Active-lease cleanup protection.
- One-start-per-provider fan-out, truthful coordinator/branch terminal states, invalid branch bounds, and duplicate-provider rejection.
- Per-file synthesis agreement when candidates differ elsewhere.
- Wrong-scope authorization rejection and regression assertions proving caller-supplied `authorized_by` is not an accepted parameter.
- Failure-atomic integration, unrelated-file preservation, clean-index restoration, no-op integration rejection, and authorized rollback.
- End-to-end runtime integration using persisted grants.
