# SORA's move call: real destinations, pace and an arrival pose

Model name: **Opus 5.5**. Checkpoint **2026-10-06 09:39:05 +01:00**, Europe/London. Status:
**implemented, component-tested only.** This moves [V1.md](../V1.md) step 5 forward. Owner
report: "the json schema hasn't been updated yet to actually allow SORA to move. This still uses
the old restricted test version."

## What was restricting her

| | The renderer could already do | The model was allowed to ask for |
|---|---|---|
| Walking | `move_to` any desktop point, at any speed (running gait from 450 px/s) | walk to the owner's **pointer** only |
| Speed | walk or run | nothing to choose: every walk used a fixed 800 px/s, so she **always ran** |
| Sequences | a pose after travel | one action per turn |

The prompt also told the model: "No coordinates, other destinations, physical effects or
commands".

## Changes

- **`Move` contract** (`src/sora/contracts/companion_call.py`):
  - `target`: `pointer`, `window` (with `window` set to a `list_windows` reference issued this
    turn) or `screen` (with `monitor`: `primary` / `pointer` / `other`, and `place`: `left` /
    `centre` / `right`);
  - `pace`: `walk` or `run`;
  - `then`: an optional pose to take on arrival.
  - A window reference is required for, and only for, window targets.
  - Old calls such as `{"op":"move","target":"pointer"}` stay valid. The exported
    `companion-call` schema was regenerated.
  - The model never supplies coordinates; Core resolves every destination. This follows the
    vision's rule that guardrails belong on the small brain.
- **Instructions:** the model's movement guidance now describes each target, when to use
  `list_windows` first, pace, arrival poses, and that moving never clicks or changes a window.
- **Resolution in a turn** (`src/sora/runtime/read_turn.py`): a window reference resolves to the
  window seen in this turn's `list_windows`. Stale references (older than 60 s), minimized
  windows and windows without a position are refused with a reason.
- **Destinations** (`SoraRuntime._move_destination`):
  - window: the ground (work-area bottom, above the taskbar) beneath the window's centre, on its
    monitor. The avatar has physics, so a mid-air target would only fall there;
  - screen: 15 %, 50 % or 85 % across the chosen monitor's work area, at ground level. "Other"
    means a monitor other than the pointer's, and is refused when there is only one;
  - pointer: unchanged.
- **Avatar session** (`src/sora/embodiment/local_player.py`):
  - `walk_to(…, pace=, then=)`. Walking is 300 px/s, the walking gait; running is 800 px/s.
  - The arrival pose becomes the resting state that the watch loop restores when the walk ends,
    so it never interrupts the walk.
- **Replies** name the pace, destination and arrival pose, and still say the message "confirms
  dispatch, not arrival".
